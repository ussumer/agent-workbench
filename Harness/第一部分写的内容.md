## sandbox
1. 具体的,因为skill有着安全问题,sandbox是必要的
2. 用opensandbox来管理docker容器
3. sandbox需要用户作用域的隔离和sandbox的预热
4. 只要有一个用户把空闲沙箱占用了,就再创建一个sandbox预热
5. 沙箱的组织结构![Pasted_20260914213108_第一部分写的内容](../../attachments/%E7%AC%AC%E4%B8%80%E9%83%A8%E5%88%86%E5%86%99%E7%9A%84%E5%86%85%E5%AE%B9/Pasted_20260914213108_%E7%AC%AC%E4%B8%80%E9%83%A8%E5%88%86%E5%86%99%E7%9A%84%E5%86%85%E5%AE%B9.png)
	1. ![Pasted_20260914213751_第一部分写的内容](../../attachments/%E7%AC%AC%E4%B8%80%E9%83%A8%E5%88%86%E5%86%99%E7%9A%84%E5%86%85%E5%AE%B9/Pasted_20260914213751_%E7%AC%AC%E4%B8%80%E9%83%A8%E5%88%86%E5%86%99%E7%9A%84%E5%86%85%E5%AE%B9.png)
	2. backend,你也可以去用别人提供的,具体的,就是实现一个沙箱各种操作,是一个复杂的类呢
	3. sanboxbackendproxy是代理层,用户去绑定这个,而不是沙箱,可以实现沙箱的热替换,保存内存地址不变
	4. sandboxmanager做生命周期的
	5. sandboxhealthmiddleware就是沙箱健康检查的中间件 在before_agent之前检查,就是和用户和智能体交流之前检查
## skills
1. skill的执行和存储分离,在sandbox实现,是为了安全,在本地数据中存储,是为持久化
2. skill需要渐进式发现/渐进式披露
3. 运行时要按照需要,自动创建/下载skill
4. 需要持久化,就需要自己的文件后端
5. skill-manger,用一个skill来执行
## context manager

 1. 有关input context ,分为agent.md,用户偏好,技能的frontmatter,上下文,和委派任务之后的返回
 2. 有关压缩,有deepagent内置的offload来剪裁,不让一个文件里的太大
 3. 摘要会先保存上下文,实现上下文持久化
 4. 可以将摘要的功能返回为一个tool,实现一个手动摘要,可以让智能体在合适的时机自己摘要
## longterm memory
1. 这边是用mongoDB来存储的短期记忆
2. 用langchain的checkpoint机制来做的自动持久化记忆
3. 长期记忆在preferences.md
4. deepagent支持用数据库来虚拟目录存储,存储的时候,可以就转化为String就很自然可以存了,比如,刚刚checkpoint里面就是一个打不开的blob文件
5. 注入这件事情,用中间件实现,抽取出对应user的长期记忆来注入
## 人工介入
1. 写在tools里面,让智能体来抉择
2. 具体的,需要在子智能体的提示词里面,告诉他
3. 后端里面实现command(resume)补充内容以及对话恢复
