# Harness 面试项目分章学习路线

这组文档面向已有项目整体脉络、正在准备日常实习面试的读者。目标是把设计要求、代码机制和验证证据对应起来。无需背完整源码，也不要直接把 AI 生成的实现当成自己已掌握的能力。

## 如何使用

每次只读一章，按“机制解释 → 指定函数 → 案例 → 自检 → 确认”推进。首次阅读先把辅助函数当黑盒，只有解释不通时才展开。每章可分多次完成，不按阅读时长判断掌握程度。

你可以带着本章编号和一段笔记回来，例如：“Part 02：我理解冻结参数；Mongo 条件更新还有疑问。”后续讨论集中补齐这一章，不默认切回逐问面试。确认由你决定，文档生成、测试通过和用户掌握是三种不同状态。

| Part | 主题 | 本章完成后应该能解释 |
|---|---|---|
| [01](01-chat-run.md) | 一次聊天运行 | 请求、后台运行、事件队列和数据库如何连接 |
| [02](02-approval.md) | 审批与授权 | 批准绑定什么，参数变化和同时批准如何处理 |
| [03](03-erp-idempotency.md) | ERP 事务与幂等 | 响应丢失为何不会双单，新采购为何仍能下单 |
| [04](04-delegation.md) | 主子 Agent 协作 | 工具分权、消息隔离和信息传递的收益与代价 |
| [05](05-state-sandbox.md) | 持久状态与沙箱恢复 | checkpoint、Store、应用记录和执行副本各管什么 |
| [06](06-skills-budget-memory.md) | 技能、预算和记忆 | 哪些地方需要验证、有限终止和持久化 |
| [07](07-evidence-interview.md) | 证据与面试表达 | 如何区分已实现、已验证、本人掌握和后续计划 |

依次完成 01–04 建立面试主线，再读 05–07 形成可靠性专题。已有整体架构可按需查阅 [architecture](../plan/architecture.md)，不要求重新从零学习。

## 确认记录

在 [PROGRESS](PROGRESS.md) 记录自己的解释和疑问。能够用一个具体案例解释机制、定位核心代码、说明一种失败边界，才适合确认本章。函数名、行号和 SDK 参数不要求背诵。

## 文档与实现边界

本文依据当前仓库源码整理。旧 [walkthrough](../../walkthrough.md) 和方案中的部分实现声明属于历史描述，不能替代现在的代码与证据。修正记录见 [HANDOFF](../plan/HANDOFF.md)，修复前评审见 [review](../runtime/harness-review-2026-10-01.md)。

完整 RSI 的冻结评测、候选晋升和回滚尚未实现；异步分析已有单独服务，但当前 analyst 图没有模型客户端。这里不把这些能力写成完整自进化系统。文档链接检查只证明文件可定位，不证明应用当前运行通过。
