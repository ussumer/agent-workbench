# T53 GDPevo 新任务真实模型难度试跑

## 目标

在当前配置模型上试跑 T52 的五个 held-out test，先报告无训练规则的 base；随后用训练材料中的完整规则做 policy-visible 诊断对照，区分企业知识缺失与组合计算错误。本包是合成资料的真实模型决策校准，不声称生产 Actor/ERP/OpenSandbox 全链路已适配新规则，不替换原技术栈。

## 前置与必读

T52；执行协议、HANDOFF、任务集说明、私有 oracle 及既有预算网关/会话账本。模型 ID 读取 /mnt/c/dev/rsi-eval/config.t46.json，密钥读取现有环境。沿用用户授权累计 50 CNY、每题 2 CNY。

## 文件边界

新增 scripts/planning/gdpevo_calibration.py 和 tests/acceptance/test_t53.py；冻结 fixture/评分器副本到独立外部 attempt。保留全部原始响应、请求、usage、错误和账本记录；不改 T52 规则、答案或历史证据，不启动训练或下单。

## 实现步骤

1. 为每题生成独立消息，只传本题公开数据、输出格式及公开契约。base 不读取训练材料或任何测试答案；policy-visible 只传训练政策文字，不能传 gold/rubric。
2. 每题一次真实模型请求，禁用 SDK 重试；输出限制 4096 tokens、网络超时 120 秒。所有请求经过既有预算网关并结算同一会话账本。保留失败，不补跑直到成功。
3. 格式契约固定并排序无意义的列表次序；由固定私有 oracle 评分，不用第二个模型充当评分器。分列加权分数、整题全对、格式/环境失败、分字段错误。
4. 先完成 base 五题；若已全部通过，停止新增调用并报告饱和。否则执行 policy-visible 五题，作为知识可见性的诊断上限，不能称训练收益。
5. 只读 gate 核验请求边界、真实调用、原始响应和评分汇总。至少一次试跑不能证明模型难度普遍性或统计显著。

## 验收条件

五题 base 有独立请求/原始响应/usage及私有评分；在非饱和且没有连续环境失败时，有五题 policy-visible。失败计入分母，网络连续两题失败即停止并报告。验证不重新调用模型。明确这是内容难度试跑，尚未证明 TRACE/Curator 学习增益或生产工具执行成功。

## 检查命令

python3 scripts/plan_guard.py check → next → packet T53。实现后 uv run --frozen python scripts/planning/gdpevo_calibration.py run；最后 python3 scripts/gate.py T53，只读核验不会新增调用。

## 失败处理

同一环境问题两次失败或约 20 分钟无实质产出立即停下讨论，不重启整栈或扩展适配器。预留金额保持直到完成usage结算，未知usage保留保守额度。格式失败和业务失败如实分列，不用改评分或删失败改善成绩。

## 完成证据

独立 session/report、每题 request/response/result/metrics、model_calls.jsonl、输入/评测代码 hash、副本及会话 ledger，T53 receipt；HANDOFF 记录真实结果与限制。
