# T51 高难度重复真实训练前后消融

## 目标

在现有容易公开案例之外，使用真实生产 Actor 和 OpenSandbox 对四个组合条件做 fixed（无学习技能）与 curated（同一训练材料提炼的技能）对照。每个条件至少重复两次，报告逐次成功、失败、模型调用、费用和独立裁判；若 fixed 基线饱和，增加重复或组合难度，不把高基线包装成学习提升。

## 前置与必读

T50；`docs/runtime/evolution-pilot.md`、`docs/runtime/learning-space-baseline.md`、TRACE 原文及执行协议。复用 T47 的真实训练 Episode 和 Curator，不重跑旧的两案例小样本。

## 文件边界

`scripts/planning/challenge_pilot.py`、`tests/acceptance/test_t51.py`、本任务证据目录和外部评测目录。不得改写既有 T47/T48 证据，不进行模型权重微调。

## 实现步骤

1. 固定 `deadline-budget`、`deadline-budget-missing`、`business-infeasible`、`no-partial` 四个公开组合条件，每个条件 fixed 重复两次。
2. 复用同一训练材料调用真实 Curator，冻结 curated Skill；在完全独立初态上重复相同条件。
3. 独立 judge 按业务成功、正确澄清/拒绝、零额外订单和真实计算结果评分；保留全部 attempt 和预算账本。
4. 如果 fixed 成功率达到饱和，追加重复或提高条件交互难度，直到比较能区分或有依据地报告没有提升。

## 验收条件

两组均有四个条件的重复真实 attempt；每个 attempt 有 runtime freeze、Episode/ERP/独立评分和费用记录。报告必须给出总体与逐条件成功率、全部重复通过率、失败分母，以及是否达到预先声明的提升标准。不能把 Curator 生成成功或组件测试通过当作业务提升。

## 检查命令

`python3 scripts/plan_guard.py check`、`next`、`packet T51`；真实实验完成后运行 `python3 scripts/gate.py T51`。live gate 只读验证固定外部会话，不重复生成模型调用。

## 失败处理

端口、服务、预算或模型失败保留在分母并区分环境/业务原因；不得增加单次上限、删除失败或改评分阈值。两次有依据修复仍失败或约 20 分钟无实质进展时停止并沟通。

## 完成证据

外部实验目录、Curator 原始输出与技能 hash、每次 attempt 的源码/运行时冻结、Episode/ERP/独立 judge、预算账本、汇总报告及 `T51` receipt。
