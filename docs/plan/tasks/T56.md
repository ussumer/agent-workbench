修复T55中反馈过粗、解释与JSON脱节、Curator技能未验证的问题。实施公开约束诊断、训练失败的一次真实修正、真实Curator候选、在train验证并拒绝退化、冻结后同协议fixed/raw/curated开发test消融。保留所有失败，明确新输出协议改善与技能增益的区别。

T55；执行协议、HANDOFF、规划契约、T55报告及训练入口。沿用50元会话总额及单次2元额度，模型配置读取。旧baseline、v1实现及冻结证据不修改；T54另线程暂停。

## 实现步骤

1. 只读旧train尝试，补具体公开约束诊断；不传oracle答案。
2. 三个旧失败任务各一次诊断修正，保存原始调用；提炼一次真实Curator候选，使用先分析后decision的输出协议。
3. 同协议train fixed/curated各五题，按不退化且有改善选择技能，未胜出则保留旧bank；选择仅看train。
4. 冻结后fixed/raw/curated各五题开发test，没有测试oracle反馈或测试重试。
5. 验证请求边界、评分、版本/hash和真实调用，准确报告收益与限制。

至少8项业务断言，诊断从公开候选重算预算、运费、盈余及kit闭包；不能静默替换模型输出。旧T55 verifier仍能验证冻结证据。真实修正、Curator、候选训练验证和三组test完整且只读核验通过。业务失败保留，不以gate通过当学习成功。
