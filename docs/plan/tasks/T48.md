# T48 操作失败对照与澄清/拒绝反事实

## 目标
补足真实 TRACE 操作级失败证据；在真实业务栈检验条件组合、缺失来源澄清、完整证据不可行拒绝与可行控制。

## 前置与必读
T47；execution/HANDOFF、planning 契约、TRACE 2.2 与 learning-space-baseline。

## 文件边界
src/agent/tools/planning.py、planning/actor.py、evolution/curator.py；scripts/planning/decision_pilot.py 与既有评测入口；tests/acceptance/test_t48.py。

## 实现步骤
增加 planning_decision，记录模型的澄清/拒绝声明及当前 revision，不提供固定求解器。保留实际失败 computation 与成功操作的部署视图，Curator 用同一公开反馈输入；在新组合及反事实运行冻结文字技能。来源缺失在真实 ERP HTTP 响应边界明示遮蔽字段，保留原响应，禁止编造报价。

## 验收条件
组件校验身份/revision/声明约束和操作成功失败对照；真实模型的可行组合、来源缺失、业务不可行三案例由独立裁判核对，正确澄清/拒绝须无写入。所有失败、费用、bank/源码 hash 保留，未测出增益如实报告。

## 失败处理
不自动提高额度或删除失败；环境故障与业务错误分列。缺真实证据不记 done。

## 检查命令
python3 scripts/gate.py T48。live 只读既有 decision-pilot evidence，不反复运行模型。

## 完成证据
组件 JUnit、独立 judge/ERP/decision/Episode、真实 Curator 输出、训练配对 hash 与全部费用账本。
