# T59 动态逐回合技能选择接入实验 Actor

## 目标

把 T58 的四组 scoped skill bank 接入已有 `PlanningTraceMiddleware`，让真实 planning Actor 在每个模型 action turn 根据当前历史与观测重新选择有序技能，并记录选择、正文 hash、工具轨迹和结果。先完成零模型协议校验，再做一次额度受控的真实 Actor 试跑；生产 assignment 保持不变。

## 前置与必读

T58；`docs/plan/execution.md`、`docs/plan/HANDOFF.md`、`docs/runtime/paper-fidelity-audit-2026-10-03.md`、`docs/runtime/self-evolution-spec-2026-10-03.md`、`docs/runtime/gdpevo-procurement-taskset-v3.md`。

## 文件边界

复用现有 DeepAgents/LangGraph、MongoDB、OpenSandbox、`PlanningTraceMiddleware` 和 `ComputationService`；只改训练隔离分支的实验 runner、bank 载入验证、测试、报告和计划证据。不恢复 T38，不改生产 bank、ERP/MCP 合同或 T54 私有裁判，不挂载 v3 私有答案。

## 实现步骤

1. 增加 scoped bank 的严格载入函数，校验四个技能的 scope、唯一 ID、正文 hash 和无生产 assignment。
2. 将 bank 载入接入现有真实 planning Actor，使 selector 每个模型回合接收当前历史和全量描述，返回有序 ID 后再注入正文；记录 selector 输入、选择、正文 hash、Actor 输出和工具观察。
3. 用零模型替身验证空选择、变更选择、未知/重复选择拒绝、跨回合不继承正文、失败计算不发布旧状态。
4. 只在零模型协议证据通过后，使用已有额度最多做一次真实工具 Actor 试跑；失败保留并停止，不用 v3 test 结果倒选技能。

## 验收条件

- scoped bank 载入后保留四个独立技能和 body hash，重复/越权/损坏输入失败关闭。
- 每个 Actor model turn 都调用 selector；选择序列可为空、可变、不能含未知或重复 ID；下一回合不继承上一回合正文。
- selector 使用当前历史与工具观察，Actor 获得的正文与记录 hash 一致；Mongo episode 保存 `turn_started`、`turn_grounded`、`turn_action`、selector/Actor 调用和工具结果。
- computation 工具经过 OpenSandbox，成功结果才发布；失败不覆盖旧状态。该项复用既有 T38/T41 evidence，新增运行只读核验。
- 真实试跑和任何失败均保留；不宣称学习增益或完整 TRACE/GDPevo 复现；production assignment 永远为 false。

## 检查命令

`python3 scripts/plan_guard.py check` → `next` → `packet T59`；随后运行 `pytest tests/acceptance/test_t59.py -q` 和 `python3 scripts/gate.py T59`。真实调用使用现有 50 CNY 会话剩余额度和每 attempt 2 CNY 上限，不能重复 T57/T58 train。

## 失败处理

零模型协议失败时保留失败报告，不启动真实模型或服务试跑；同一问题两次有依据修复仍失败，或约 20 分钟无实质进展，停止并报告。真实 Actor、沙箱、模型网关或证据归档失败均保留原始 attempt，不重跑同一签名。

## 完成证据

gate receipt、零模型 JUnit、动态证据报告、bank/selector/episode manifest、真实试跑目录（若执行）、Git commit 和 HANDOFF 记录结果、成本和边界。组件通过不等于 v3 业务学习增益。
