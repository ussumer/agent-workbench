# T40 独立规划Actor工具与逐单审批恢复接线

## 目标
增加与课程最低价报告模式分离的 DeepAgents 规划图。Agent 可以读取公开问题、查看必要来源、用通用kernel自己组织计算、检查候选、提交方案并逐单等待用户审批。组件接线先验证，不称真实模型行为/Prime/TRACE通过；完整场景必须在T38恢复验收和具体新增模型预算后另包实测。

## 前置与必读
T37、T39、T35；planning、chat、skills-memory、implementation-notes、实施现场。execution/HANDOFF、check → next → packet。

## 文件边界
src/agent/planning/actor.py、src/agent/tools/planning.py、公开审批ID与chat/stream适配；必要规划API入口；tests/acceptance/test_t40.py；相关契约/说明。T38实现/配置/服务不动，旧课程Agent与技能保持。

## 实现步骤
1. 通用公开问题和可行性检查工具；只有受信配置决定owner/thread/goal，拒绝模型越权；规划工具不提供私有oracle或固定求解器。
2. 独立DeepAgents graph，实际模型来自ModelConfig，Mongo checkpointer/Store；接入现有kernel工具，不允许shell固定planner回落。
3. planning_submit保存T39草案后按单interrupt，resume只认正式服务端审批，不凭模型文字或Command(resume)自批；重放保持interrupt顺序及operation。
4. 同一待批动作使用每单独立公开审批ID，关联框架连续interrupt序列而不复制新approval/operation；SSE复用既有review UI形状；首次approve后第二单独立等待，重放不得重新全量prepare。
5. HTTP公共目标入口从真实ERP生成问题，使用可信线程归属；恢复后的方案/成功部分与拒绝结果可见；版本变化阻止旧候选写入。

## 验收条件
至少10项组件检查：模型schema无owner/grant/operation/approve参数，真实ERP问题保存、非法候选/缺scope拒绝、独立graph工具权限与无裁判、真实Mongo checkpoint+官方DeepAgents中断恢复、正式API两次逐单审批各一次实际Java订单、拒绝不继续写、直接伪造resume无授权不写、graph对象重建、SSE逐单ID/版本检查。组件测试允许明确scripted model，真实Mongo/MCP/Java不可替换。原T39/T13回归不降低。无付费模型、无kernel操作；实际Actor自组织持久计算和反事实/学习空间需未来完整live包，不以组件通过替代。
