# T64 全量 v3 进化训练与独立重复消融

## 目标

在完整 v3 的 20 道 train 和 20 道 held-out test 上运行一次真实 GDPevo/TRACE 进化训练。Curator 必须同时看到原题公开输入、真实输出、逐字段失败诊断、算术审计和成功/失败配对；候选技能按业务组和操作拆分，加入 train-only few-shot 与 reflect-3 修订，再用 train validation 选择。最终在完全不回流反馈的 held-out test 上比较 fixed、few-shot、候选技能和动态选择四个 arm，并至少三次重复，保留所有失败和费用。

2026-10-05 对照论文后的执行澄清（不缩减验收）：所有 arm 使用同一 DeepAgents/OpenSandbox 计算 Actor，计算数据持久于 Mongo，每条 attempt 独占 owner/沙箱。few-shot 指用每组五道 train 的正确答案提炼技能，再以该技能执行新题；不能把直接塞几个示例当论文 few-shot。reflect-3 指三轮完整 train 做题→评分→修订 bank，不能连续三次改写同一轨迹冒充三轮学习。dynamic 必须调用既有逐回合 PlanningTraceMiddleware，不能固定取首项。原 v3 test 已被 T57/T58 使用，作为重复开发评测报告；独立封存验证必须使用本轮未参与训练、选择或修订的新验证输入，单独披露来源与难度，不冒称原 test 未见。

## 前置与必读

依赖 T63。阅读 `docs/plan/execution.md`、`docs/plan/HANDOFF.md`、`docs/runtime/paper-method-diagnosis-2026-10-05.md`、`docs/runtime/gdpevo-procurement-taskset-v3.md`、`docs/papers/rsi/gdpevo/2608.03764v1.txt` 和 `docs/papers/rsi/trace/2608.22793v2.txt`。复用 T54 冻结 v3 fixture、T62 反馈边界和既有 `ComputationService`，不读取私有答案生成训练提示。

## 文件边界

修改训练隔离分支的 T64 runner、共享候选选择器及其受影响测试/历史只读核验、报告和计划证据。生产技能 assignment、ERP/MCP 合同、私有裁判、v3 fixture 与既有 T55/T57/T58/T63 attempt 不得改写。真实模型调用只通过已配置 gateway，OpenSandbox/ Mongo 仍是计算和状态边界。

## 实现步骤

1. 冻结 20 train、20 held-out test、模型身份、提示、随机/温度、运行预算和源码 hash。先运行 fixed train，失败最多一次公开诊断修订；Curator 只收到 train 公开资料。
2. Curator 先按业务组和操作提炼聚焦技能，再对失败轨迹执行一次 reflect-3：诊断、提出修正、用同题 validation 检查修正；不得把 test 或私有答案放入上下文。
3. 在同一 train validation 上比较 fixed、few-shot 正确训练对照、聚焦技能和动态 selector。按用户 2026-10-05 明确决定，取消逐题零退化否决：总体均分和业务成功数不下降，且至少一项提高即可接受实验候选；两项持平时沿用实测 token 至少减少 10% 的效率规则。逐题退化完整报告，仅作诊断。训练可继续探索未胜出的候选并保留当前最佳版本，不因一题退化停止学习。
4. validation 重复按 (task_id, repeat) 配对、合并全部重复判定，不能挑最好一次；单次 validation 必须标明不确定性。test 每 arm 至少三次，不反馈、不重修、不倒选；只用于报告泛化和重复稳定性，不参与晋升判定。三轮反思训练、三次冻结 bank 测试和多次独立训练是不同概念，必须分别计数。
5. 明确区分机制闭环、train validation 改善和 held-out 泛化；不因均分上升或脚本通过宣称真实业务学习成功。生产 assignment 保持不变。

## 验收条件

20 train 和 20 test 均有匹配的 fixed/训练对照；Curator 输入 hash 可重放且无私有答案；few-shot、reflect-3、聚焦技能和 selector 的来源与选择可审计；test 每 arm 至少三次且无 test feedback；所有业务、格式、网关和超时失败保留在分母；报告同时给出总体、逐组、逐题和重复统计，并明确是否达到预先声明的总体提升标准。逐题退化必须报告，但不作为自动否决条件。

## 检查命令

`python3 scripts/plan_guard.py check` → `next` → `packet T64`；随后运行 `python3 scripts/gate.py T64`。live 检查只验证固定外部 attempt，不重复生成模型调用。

## 失败处理

网关 429、服务不可达、模型格式错误、沙箱失败和业务失败都保留原始 evidence；同一问题两次有依据修复仍失败或约 20 分钟无实质进展时停止并报告。不得缩小到两题后把 T64 登记完成，不得用 test 结果修订技能，不得修改评分阈值或删除退化结果。
