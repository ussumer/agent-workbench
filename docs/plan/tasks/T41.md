# T41 规划 Episode 聚合与冻结技能逐回合编排组件

## 目标

目标：同一业务 goal 跨 chat/resume/run 聚合一条 Episode；真实模型调用前依据当前可见状态及全部冻结技能描述选择有序 ID，按序注入精确正文，下回合重新选择。空 bank 是诚实的固定基线，不人工伪造学习策略。

## 前置与必读

前置 T40/T35/T32；先读 execution/HANDOFF 并运行 check → next → packet。阅读 TRACE §2.1–2.3/Algorithm 1–2 与机制核查，保留后续层级初始化/成功失败对照/学习空间/真实模型验收要求。

## 文件边界

文件范围：src/agent/evolution/、planning Actor、正式 API run 生命周期、Mongo index、默认规划装配、tests/acceptance/test_t41.py 和相关契约。旧课程模式保留，T38 不运行/修改。

## 实现步骤

实现：独立不可变文字 bank、goal 首次运行绑定后跨恢复固定；owner/scope 隔离、hash 校验失败拒绝；记录每回合可见输入、全部描述、有序选择、正文读取、动作与完整原始工具结果，避免 offload 丢失原文；大事件分块，写入失败显式失败。选择器使用配置 Actor 模型及同一累计预算，记录独立角色。Episode 保留全部 run/resume、审批/实际订单和资源；采购成功只由独立反馈判定，环境失败不作策略反例。bank 仅是文字知识冻结，不冒称完整环境 Snapshot 已实现。

## 验收条件

组件验收至少12项：正式 API 多次审批恢复聚合、graph/service 重建、在途指针变更/撤回不改变 bank、并发/owner/scope 隔离、正文损坏拒绝、每模型回合重选/不累计正文、ID顺序/非法选择拒绝、选择器预算、原始大结果、记录失败不继续调用、真实 provenance、未评分不成功。真实 Mongo/checkpoint/Java/MCP，模型明确 scripted，仅组件；原 T40/T07 回归至少38，不降低已有业务断言。
