# T37 多约束采购决策环境与独立裁判

## 目标
落实用户 2026-10-03 场景升级方向的第一包：真实 ERP 数据适配、版本化规划约束/来源/方案、来源不足与业务不可行分离、独立小实例穷举裁判。不是固定订单答案评分，不是 Actor 的自动 planner。

## 前置与必读
T35；场景升级提案、planning 契约、ERP 契约、verification。保留课程与旧 pilot；独立评测工作区 SE00 仅是历史协议基础，不代表新场景已实现。

## 文件边界
src/agent/planning/（公共数据与校验，无求解器）、scripts/planning/（私有控制面裁判）、fixtures/planning/、tests/acceptance/test_t37*.py、相关计划/契约/运行文档。不得把裁判/最优解挂载进 Actor 沙箱或注册成 Actor 工具。

## 实现步骤
1. 明确预算、交期、必需量、可选优先级、允许部分满足及供应商拆单语义；用整数分计费。
2. 数据适配只接受实际查询结果；seed 只供确定性实例及真实 Java 初始化，不在 live 路径替代 ERP。
3. 公共方案检查可行性和来源，私有裁判独立枚举目标值，接受同目标的不同合法方案；未知来源不算业务冲突。
4. 约束/来源修订产生新 revision，旧方案明确拒绝，记录受影响物料。
5. 确定性对抗/生成式实例与真实 Java HTTP 集成验证。

## 验收条件
至少 25 项确定性测试：提案例、替代解、非最优合法解、预算/交期/拆分/过量/停用/无关系、报价引用、缺失/冲突/不可行区分、优先级、变化与旧方案拒绝、小实例独立参照。至少 2 项真实 Java 集成测试：查询得到同一场景数据、改变 seed 导致计划目标改变且订单状态仍查询自 ERP。预算/目标不存在硬编码答案。枚举超限显式拒绝，不报最优。组件 gate 不声称模型、沙箱 kernel、多单审批或学习完成。

## 检查命令
python3 scripts/gate.py T37

## 失败处理
保留失败 attempt。服务不可用不跳过；不得把集成改为 fixture 代替，不改验收分母。

## 完成证据
完整 gate receipt、JUnit、state/HANDOFF；review 保持 not_reviewed。下一包先核实 OpenSandbox 持久 Python API，真实跨回合、owner/session、取消与恢复证据后才称 Prime 持久计算。
