## 实现步骤

1. 把所有规划启动命令替换为实际验证命令，列出服务、配置、端口、日志与停止/重置。
2. 按一条创建订单、一条报告、一条技能恢复链路写代码阅读说明，引用真实文件/函数。
3. 在新的项目测试卷/namespace做安装、启动、seed、smoke、停止、重启和reset，避免破坏用户开发数据。
4. 汇总课程覆盖、版本锁、证据索引、已知限制及后续RSI边界；所有应用任务done后也不得宣称用户已经审阅。

## 验收条件

- 只按README即可启动并完成烟测，命令无占位服务/不存在脚本。
- 数据默认保留，reset仅影响Demo范围；不泄露密钥，不误删其他容器。
- 交接指向实际代码和证据，明确Demo限制和用户审核状态。
- 对应 tests/acceptance/test_t24.py 必须运行且断言数不少于 8 个测试用例；数量只是防零收集底线，不能代替上面的行为覆盖。
- 所有 required checks 通过；不能跳过真实服务测试后登记完成。
