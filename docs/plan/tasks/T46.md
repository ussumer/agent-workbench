# T46 真实规划 Actor 基线与预算修订评测入口

## 目标
在真实独立 ERP/Mongo/MCP/OpenSandbox/Agent Protocol 上运行配置模型，经正式 goal/chat/resume 形成多单与计算证据。独立裁判核对可行性/目标和实际订单，不向Actor提供解。验证预算2500->2200时复用持久报价并重新审批。

## 前置与必读
T45；execution/HANDOFF、规划契约、持久计算、学习空间。用户2026-10-04新增总50CNY授权，单attempt2CNY，所有Actor/selector/Curator和重试合计；未知调用保留预留。

## 文件边界
scripts/planning/live_baseline.py、tests/acceptance/test_t46*.py、运行说明；复用独立评测器已有隔离服务与预算网关，不重写协议/业务系统。必要Actor修复仍保留既有契约。

## 实现步骤
登记新额度会话，先冻结源码/JAR/依赖与镜像证据，worker只收公开goal和用户交互。正式POST goal、chat、逐单resume；预算修订先PATCH、验证旧批准拒绝，再让同Actor重算。采集完整Episode与计算操作、状态、实际ERP；控制面独立评分并hash绑定。支持prepare零生成。完整环境Snapshot另验，不将源码归档当完整Snapshot。

## 验收条件
至少12个评测/费用/隔离unit检查，68个已有unit回归，3个live证据断言：完整源码/真实服务/真实模型/成本保留；baseline双单与最优合法结果；预算修订旧批准失效、同Episode和选择性持久数据复用。缺服务/额度/模型证据、零计算、宿主替代或业务不一致均失败，不降低门槛。保留所有attempt；不宣称TRACE学习收益。

## 检查命令

live verifier使用PLANNING_LIVE_SESSION指向本轮会话，不重复调用模型；模型执行入口为python3 scripts/planning/live_baseline.py。

## 失败处理
每次新attempt，未知状态计全额预留，超时取消run并等待计算实际结束，故障只针对根因修复。不自动放大额度或上限；无假live回退。

## 完成证据
receipt/JUnit、全部attempt manifest、原始事件、Episode、计算JSON、实际ERP和独立judge。先证实真实Actor的决策/状态能力，后续再做条件校准、Curator及组合迁移。
