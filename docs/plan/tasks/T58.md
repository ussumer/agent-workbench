# T58 按业务组拆分的 GDPevo 技能库

## 目标

将 T57 的单一全局技能改为按报价、整包、套件、修订四组分别生成和加载的 scoped skill bank，验证 TRACE 的 skill-aware grouping 是否减少跨规则干扰。

## 前置与必读

T57；`docs/plan/execution.md`、`docs/plan/HANDOFF.md`、`docs/runtime/gdpevo-procurement-taskset-v3.md`、`docs/runtime/self-evolution-spec-2026-10-03.md`。

## 文件边界

只改训练隔离分支的 Curator runner、验证、测试、报告与计划证据；不改生产 bank、旧 v2、T38 或 ERP/MCP/OpenSandbox 实现。

## 实现步骤

复用 T57 已保存的 train 首次输出和单次诊断修正。每个业务组独立调用一次 Curator，仅接收该组五道 train 的公开 policy evidence、尝试和诊断。生成四个 scoped skills；train 上与固定控制逐题比较，按无逐题退化和成功数/均分晋升。test 只加载对应 group skill，不回传 test 反馈；固定控制复用已有证据。

## 验收条件

Curator 输入按 group 隔离且无 test/私有答案；四个 skill 的 scope/hash 独立；train-only 晋升；fixed/scoped test 同任务对照；失败、网关拒绝和未晋升候选保留；生产 assignment 永远为 false。

## 检查命令

`python3 scripts/plan_guard.py check` → `next` → `packet T58`；`uv run --frozen pytest tests/acceptance/test_t58.py -q`；`python3 scripts/gate.py T58`。复用 50 元累计/单调用 2 元 gateway，不重复 T57 train。

## 失败处理

任一 Curator 环境失败保留并停止该组；同一问题两次修复或约20分钟无实质进展停止。不得用 test 结果选择技能或强行晋升。

## 完成证据

外部 attempt 保存四次 Curator、train/test 请求响应、skill bank、选择结果、manifest；gate、Git commit 与 HANDOFF 记录结果和边界。
