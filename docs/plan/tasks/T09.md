# T09 用户沙箱池、稳定代理和恢复

## 目标

保留课程预热、认领、登记、热替换和用户隔离能力。

## 前置与必读

前置任务：[T07](T07.md)、[T08](T08.md)。需求：R09。

- tests/integration/test_sandbox_lifecycle.py、tests/acceptance/test_t09.py

允许补充本任务所需小型测试/配置；不要重构无关模块。最终向用户报告真实文件路径，不保留本文目录中的省略号作为实际路径。

## 实现步骤

1. 实现状态机、用户锁、预热池锁、Mongo登记和重连优先级。
2. 代理显式委托所有协议方法，replace_backend后Python对象身份保持；generation变化可观察。
3. 初始化全部完成再发布backend，认领后受管理后台补充预热，防泄漏与双重认领。
4. 同用户sandbox操作串行化；不同用户隔离；并发health失败只重建一次。
5. 真实删除执行容器并恢复，API重启通过登记重连，清理只针对项目资源。

## 验收条件

- 相同user不同thread共享proxy；不同user不同容器且读不到对方文件。
- 预热同时认领不重复，失败初始化不发给运行，恢复后规则重新上传。
- 旧调用失败不自动重放副作用命令；不会大量残留容器。
- 对应 tests/acceptance/test_t09.py 必须运行且断言数不少于 14 个测试用例；数量只是防零收集底线，不能代替上面的行为覆盖。
- 所有 required checks 通过；不能跳过真实服务测试后登记完成。
