## 实现步骤

1. request_order_info使用框架interrupt，验证缺字段和反复补充，不能猜未指定值。
2. 配置order_create/order_update的interrupt_on；持久化pending_action和冻结payload_bytes、hash、operation_id。
3. 实现可信resume、内部批准验证端点和工具包装器的上下文注入；MCP写无授权拒绝。
4. approve/reject按锁版框架形状恢复原thread；重复resume条件更新，仅一个执行者。
5. 构造响应丢失、子图重放、修改参数、过期审批、版本冲突、跨用户攻击测试。

## 验收条件

- 补充和审批分别中断；approve前ERP零写，reject后零写。
- 同批准重复提交只产生一单；已批准内容变更必须重新审批。
- checkpoint和pending_action重启恢复，内部授权不进入模型/SSE。
- 对应 tests/acceptance/test_t12.py 必须运行且断言数不少于 16 个测试用例；数量只是防零收集底线，不能代替上面的行为覆盖。
- 所有 required checks 通过；不能跳过真实服务测试后登记完成。
