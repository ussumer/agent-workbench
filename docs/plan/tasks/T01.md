# T01 固定业务种子与契约测试数据

## 目标

所有模块使用同一份稳定、可重置的数据和协议样例。

## 前置与必读

前置任务：[T00](T00.md)。需求：R02。

- [contracts/erp.md](../contracts/erp.md)
- [contracts/chat.md](../contracts/chat.md)
- [contracts/skills-memory.md](../contracts/skills-memory.md)

## 文件边界

- fixtures/seed-v1.json、fixtures/schemas/
- tests/fixtures/、tests/acceptance/test_t01.py

允许补充本任务所需小型测试/配置；不要重构无关模块。最终向用户报告真实文件路径，不保留本文目录中的省略号作为实际路径。

## 实现步骤

1. 按ERP规格写供应商、物料、关系、库存；包括停用对象和明确无供货关系。
2. 创建创建/修改订单、两层中断、SSE分片、技能manifest的有效/无效JSON fixtures。
3. 独立计算固定预期：1275.00、1530.00、87.00、1533.00、2553.00；记录每项输入来源。
4. 定义测试namespace和清理边界；seed不得包含随机日期或启动时变化的价格。

## 验收条件

- 预警集合精确为P001/P003/P004，建议量42/15/30。
- 所有有效样例schema通过，错误金额/重复物料/缺字段等被拒；无效样例与有效样例分目录。
- Java初始化、报价站和验收都引用同一seed源，不各抄一份数字。
- 对应 tests/acceptance/test_t01.py 必须运行且断言数不少于 10 个测试用例；数量只是防零收集底线，不能代替上面的行为覆盖。
- 所有 required checks 通过；不能跳过真实服务测试后登记完成。

## 检查命令

```bash
python3 scripts/gate.py T01
```

gate 的实际 argv 和报告路径以 ../tasks.json 为准；不得为本包手工编造 passed receipt。

主验收模式：unit。fake 只准用于声明的 unit/integration 模型替身，live 模式禁止。测试标准见 [verification](../verification.md)。

## 失败处理

金额或字段有矛盾先修订输入/文档并指出影响，不能修改预期以适配错误实现。
