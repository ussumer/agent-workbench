# T33 沙箱真实调用熔断与并发探测

## 目标
接通 F04 的 BreakerRegistry，让模型/技能/跨进程调用经稳定 proxy 获得同一 owner 熔断保护；不把 ERP 拒绝或脚本普通非零退出当容器故障。

## 前置与必读
T32；storage-sandbox、skills-memory、verification；安装版 backend 协议与现有错误映射。

## 文件边界
agent/backends/sandbox_proxy.py、sandbox_manager.py、custom_opensandbox.py；middlewares/sandbox_breaker.py、sandbox_health.py；middleware_config.py、api_view/api/chat.py 的错误码映射、tests/live/stack.py；tests/acceptance/test_t33.py、tests/fixtures/sandbox_service.py 的固定本地验收端点与数据库管理标记；相关契约、计划、交接。

## 实现步骤
每 manager 一个 owner registry，proxy 统一同步/异步真实调用边界。连续三次基础设施失败熔断30秒；冷却后只允许一个探测，成功关闭。execute 超时124/异常125及明确传输错误计故障；普通脚本失败、文件不存在、路径错误和 ERP 422 不计。文件 SDK 运输失败也不能被错误映射掩盖。线程安全计数/半开预占，冷却拒绝不能导致 manager 重建容器；热替换保留同一熔断身份。无宿主执行、自动重放或技术替换。

## 验收条件
至少6项真实 OpenSandbox/Mongo 操作覆盖超时熔断、普通脚本失败、同步异步共享、owner隔离、冷却恢复及单探测并发。补充文件传输故障。原T19全部28和T09/lifecycle36项回归，不降低门槛；所有失败尝试保留。命令 python3 scripts/gate.py T33。

补充原 T08 沙箱协议检查，沿用其最低12项门槛；迟到成功不能关闭新熔断的并发案例单独加入。
