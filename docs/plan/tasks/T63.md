# T63 TRACE 四阶段初始化与真实技能归因进化闭环

## 目标

完成 TRACE 风格的真实四阶段初始化和一次技能归因演化闭环，补齐当前只有动态 selector、没有训练回流的问题。

## 前置与必读

依赖 T62、T59。阅读 `docs/plan/execution.md`、`docs/plan/HANDOFF.md`、`docs/runtime/paper-method-diagnosis-2026-10-05.md`、`docs/runtime/gdpevo-procurement-taskset-v3.md` 和 `docs/papers/rsi/trace/2608.22793v2.txt`。

## 文件边界

只改隔离训练分支的实验 runner、既有计算 Actor 接口、测试、报告和计划证据；复用 DeepAgents/LangGraph、MongoDB、OpenSandbox、ComputationService 和 `PlanningTraceMiddleware`。不改生产 assignment、ERP/MCP 合同、私有裁判或 T54 任务资料。

## 实现步骤

1. 以 T62 的 train 公开视图、真实输出及计算轨迹为初始化输入。由真实 Curator 完成按任务提炼、按类型合并、按操作合并和聚焦技能拆分四阶段，保存阶段 ID、来源映射、理由与正文。

2. 在同两道 train 上用相同模型、基础提示和计算工具运行 fixed、B0、B1。B0/B1 复用 PlanningTraceMiddleware 每回合重新选择；B0 轨迹按实际选择分组，空选择进入 uncovered，成功/失败是任务标签，不伪称操作因果。一次 Curator 从 B0 公开原题、可见工具参数/结果及评分字段修订 B1；只用 train 选择，不接触 test 或私有答案。

3. 继用户取消金额限制，费用仅记录；模型/工具回合及超时仍是执行边界。新 attempt 排他创建，逐步保存原始输出、usage、bank、episode、决定、评分和失败；生产 assignment 不变。真实流程完成可登记工程任务，不代表统计学习增益、封存泛化或完整三论文实现。

## 验收条件

四阶段链可校验、聚焦技能拒绝具体实例答案、实际 selector 顺序/正文 hash 可复核、按真实技能归组不伪造使用、B0/B1/fixed 各两道 train 可重算评分、选择拒绝退化、usage 与完整 manifest 留存。所有业务失败保留，不为提高成绩再抽样。

## 检查命令

`python3 scripts/plan_guard.py check` → `next` → `packet T63`；随后运行 `python3 scripts/gate.py T63`。单元检查覆盖来源/泄漏/分组/执行预算边界与 T61 受影响协议；真实检查是一次新的闭环 attempt。

## 失败处理

Curator 输出、模型调用、沙箱执行或评分失败均保留原始证据；同一问题两次有依据修复仍失败，或约 20 分钟没有实质进展，停止并报告。不得用 test、私有答案或固定脚本补齐失败结果。

## 完成证据

gate receipt、26 个以上协议测试、四阶段 Curator 输入/输出、B0/B1/fixed episode、usage、bank、选择报告、完整 manifest、Git commit 和 HANDOFF 更新。通过只证明工程闭环，不证明学习增益。
