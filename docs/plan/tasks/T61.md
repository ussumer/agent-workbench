# T61 v3 同题 OpenSandbox 计算能力对照

## 目标

用相同v3公开train任务、模型、政策、输出合同与费用限额，比较文字决策和Agent自写OpenSandbox Python计算。保留真实多步轨迹，识别采购失败来自执行还是缺少可迁移知识。任务为合成资料的离线决策，不能冒充v3正式ERP订单adapter或技能学习收益。

## 前置与必读

T60；execution/HANDOFF、gdpevo-procurement-taskset-v3.md、paper-method-diagnosis-2026-10-05.md、现有ComputationService/PlanningTraceMiddleware。T59旧失败、T38/T51不重跑。

## 文件边界

隔离实验runner、现有live_baseline生命周期的driver接入、新离线DeepAgents Actor、协议测试、只读证据核验、计划和报告。复用Mongo持久化/OpenSandbox、真实Java/MCP/Protocol生命周期，不改业务合同或私有裁判。

## 实现步骤

1. v3 actor_view staging只读公共/训练文件；明确合成资料，不替代ERP状态。新Actor只使用通用计算工具和本题公开消息，不获得裁判或下单工具。
2. 相同DeepAgents/checkpoint/模型、temperature和输出合同；text组禁用计算，compute组只开放computation工具。正文JSON先分析再decision，同协议，不注入固定planner。
3. computation输入由通用保存接口存为公开task，Actor必须自己写计算代码并显式load_state；input-staging与Actor执行分开记账。最终decision存Mongo Episode，独立主进程运行现有评分器，判分不回传Actor。
4. 固定两个train例：packages-train-04（全局分配）、kits-train-03（配套与独立例外），text/compute各一次，不新增Curator、不选技能、不读旧test。单attempt2元、总50元、16Actor请求、无selector，全部费用/失败保留。缺环境即停、不循环试跑。

## 验收条件

真实模型四attempt均留请求/响应usage与源码/runtime身份；text组无Actor计算，compute组有Agent自写OpenSandbox成功计算且加载持久task；同题视图、提示/策略一致，只有工具开放差异；记录决策及现有评分、全部失败，ERP前后无新增订单、生产bank不变；计算副本不挂载私有裁判。任一环境失败不能通过live gate，业务低分原样报告，不靠改rubric通过。

## 检查命令

plan_guard check→next→packet T61；零模型test_t61通过后一次四attempt真实诊断；gate T61运行协议检查与只读真实证据核验，不自动重启付费实验。

## 失败处理

同问题两次修复或20分钟无进展停下讨论；每attempt最多一次，不为提高成绩重试；环境失败立即停止余下付费attempt。真实业务错误保留为本实验结果，不能称学习改进。
