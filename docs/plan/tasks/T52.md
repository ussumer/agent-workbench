# T52 GDPevo规则混合采购困难任务集设计

## 目标

构造一组可校准的采购任务，而不是把旧的预算/交期案例换名字。任务组包含 5 个训练任务和 5 个留出测试任务；训练材料只暴露企业特定规则的部分作用域，测试任务重组未在训练中共同出现的规则。每个测试评分点都有训练锚点、证据来源和可重复的业务结果。任务集设计本身不调用模型，也不声称已经产生学习增益。

## 前置与必读

T44、T50；`docs/runtime/learning-space-baseline.md`、`docs/runtime/paper-fidelity-audit-2026-10-03.md`、GDPevo 原文、`docs/plan/contracts/planning.md`。按照 GDPevo 的 rule hybridization、作用域保留、独立评分和反事实要求设计；不把“每个训练任务只有一条规则”当成论文要求。

## 文件边界

本包新增 `fixtures/planning/gdpevo-procurement-v2.json`（Actor 可见任务材料）、`fixtures/planning/gdpevo-procurement-v2-control.json`（评测控制面，禁止挂载到 Actor）、`scripts/planning/gdpevo_taskset.py`、`scripts/planning/gdpevo_oracle.py`（私有有界穷举，只用于校准 fixture）、`tests/acceptance/test_t52.py` 和 `docs/runtime/gdpevo-procurement-taskset-v2.md`。不改写 v1 seed、T44 学习空间报告或历史实验证据，不启动付费模型。

## 实现步骤

1. 定义企业特定且可观测的原子规则：正式报价版本、整包单位与现场盈余、供应商购物车运费、维修配套组闭包、有界来源缺失相关性、已购承诺与当前修订审批范围；每条规则记录触发证据、影响字段和停止适用条件。
2. 生成 5 train + 5 test 的公开材料。每个 test 规则都有 train anchor，但 test 的规则组合不在 train 出现；实体、数字、噪声和证据顺序变化，不能靠答案模板记忆。
3. 在独立 control 文件中为每项任务固定 6 个互不重复的评分点，覆盖可行性、分配、来源/澄清、差量、审批和证据引用等不同业务结果；历史已购承诺只能作为累计事实，不能把旧审批复用为当前追加授权；Actor 视图不含 expected action、rubric 或私有最优解。
4. 为测试任务提供单因素反事实：只改一个声明的条件组，并要求预期操作改变；验证无条件澄清、总选最低单价、重新购买已承诺数量和复用旧审批都会被区分。
5. 用私有有界穷举和零模型 validator 生成结构报告、答案边界和输入 hash。穷举器不进入 Actor 镜像；报告只说明结构成立；真实基线 40–60%、训练后提升约 0.1–0.3 和最终低于 0.8 是后续校准目标，不由本包伪造。

## 验收条件

公开任务恰好 5 train + 5 test；所有规则均有训练锚点，至少 3 个 test 组合从未在 train 出现，所有 test 评分点有可追溯锚点。每个任务 6–10 个权重为 1–3 的二值评分点，语义结果不重复。每个反事实只改变一个字段组且改变预期操作；缺失来源、不可行、已购承诺和审批范围不能混成同一错误。Actor 视图不得包含控制文件中的 expected/rubric/answer 字段。validator 和 16 个以上有业务断言的单元测试通过。

## 检查命令

`python3 scripts/plan_guard.py check`、`next`、`packet T52`；实现后运行 `python3 scripts/gate.py T52`。本包 gate 只做零模型 fixture/控制面校验，不启动 Java、Mongo、OpenSandbox 或模型；后续真实校准另登记任务并保留失败分母。

## 失败处理

规则组合重复、评分点泄漏、反事实同时改变多个条件或 validator 无法证明独立结果时，保留失败输出并修 fixture。相同问题两次有依据修复仍失败或约 20 分钟没有实质进展，停止并报告，不靠放宽 checker、删规则或改权重达标。
