# 验证与完成标准

## 三种检查不可互相代替

| profile | 依赖 | 验证内容 |
|---|---|---|
| unit | 可用 fake，无网络 | 解析、schema、状态迁移、金额、权限判断 |
| integration | 真实 Java/Mongo/MCP/OpenSandbox/HTTP，模型可用脚本化测试模型 | 实际数据、恢复、生命周期、协议 |
| live | 用户真实模型、搜索、图表及所有本地服务 | 完整采购助手行为和浏览器演示 |

脚本化模型可稳定触发补充/审批/超时分支，但只能放测试目录并在结果标记 test_model。live 配置若加载到 fake 类，启动直接失败。

## Gate 命令合同

T00 创建 `scripts/gate.py`，统一 `python3 scripts/gate.py TXX`；根据任务清单 required checks 执行静态检查、该包测试和指定真实服务探测。`--all` 在 T22 扩展为已实现全部确定性检查；`--live` 在 T23 扩展为真实案例。未知 task、缺测试文件、缺 report、required check 跳过均非零。

任务 tests/acceptance/test_tXX.py 是跨语言验收入口，必要时调用 Java/Vue 自身测试和 HTTP，不重新在 Python 实现一套业务逻辑。Java 仍有 JUnit 真测试，Vue 仍有 Vitest/Playwright。T00 固定 pytest markers、JUnit 报告收集和子进程超时。

格式和类型：Python ruff check + 配置好的类型检查；Java mvnw verify；Vue vue-tsc + vite build。各任务仅运行受影响检查，最终 T22 全量。检查脚本不能以 grep 出“PASS”判断成功。

## 真实模型最低门槛

demo.md 的 D01-D08 各独立跑 3 次，总计 24 次，记录全部尝试、模型 ID、输入、响应、工具轨迹、token（若上游提供）、时长和失败原因。D01/D02/D03/D04/D06 的业务金额、审批拒绝、幂等和隔离断言必须每次通过。

整体任务成功至少 22/24，且每个案例至少 2/3；失败不能涉及未批准写单、串用户或虚假产物。失败即使来自外部服务也保留，外部不可用导致门槛不满足时标阻塞，不能改分母。无需保证逐字相同或相同工具路径，但必须真实调用所需能力。

真实尝试结果与测试框架结果分开：24个trial记录各自success/reason；pytest对每个trial检查证据完整和关键不变量，再对8个案例组检查成功数，对整体检查22/24。非关键任务失败可被总体门槛容纳，但不能伪记trial成功，也不能用pytest skip/xfail容纳。最终JUnit必须全绿，门槛由明确的聚合断言验证，而非要求24个trial全部成功。实际24次模型运行只执行一次，后续断言读取同一轮结果，避免每个pytest断言重新调用模型。

额外真实外部检查：智谱搜狗搜索至少一次；ModelScope 柱状/折线/饼图各一次且浏览器资产有效。确定性测试重复跑 3 次无需重复 live 成本；真实关键流程 T23 集中执行。

## 浏览器验收

Playwright 覆盖输入、流式文本、工具轨迹、补充、approve/reject、刷新恢复、历史删除、报告下载、技能恢复、异步状态。桌面和移动截图保存，断言无页面异常/未处理请求错误，资产非空、文字不溢出、控件无重叠。
