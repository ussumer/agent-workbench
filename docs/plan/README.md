## 已确认的任务

- 根据本仓库的视频课讲义和学习笔记，规划从零实现项目。
- 用户没有课程配套 Java ERP 源码。
- 当前交付是课程 Demo Harness；技能进化限定为课程中的创建、下载、分配和持久化等能力。高级 RSI 实验留到后续，不纳入当前验收。
- 用户已选择自建采购库存 Mini-ERP，具备真实数据、业务约束、事务和可重置数据。
- 用户选择尽量保留课程技术栈和全部能力。任何调整必须先讨论并获得用户同意，执行模型不得自行替换或删减。
- 优先尽快完成；编码与业务 Agent 均使用用户提供的 DSV4.1flash。实际模型 ID、URL、协议及凭据在本地配置并验证，不从简称推断。
- Java ERP 已确认；MongoDB 和 OpenSandbox 本地部署；保留智谱搜索与 ModelScope 图表，自建报价站与技能下载资源。
- 使用摩托车配件采购场景。库存只查询；下单不改变库存。不新增入库、部分到货、财务及复杂审批。
- 单个编码 Agent 每次完成一个任务包，自动检查通过后才能登记完成；用户会审核和理解代码。
- 方案面向成本较低的编码模型，必须支持逐任务执行、明确验收、失败处理和跨会话交接。
- 初始授权为方案设计；后续用户已授权实现，并在 2026-10-01 明确授权评审后的代码修正。
- 用户明确指定 grill-with-docs，采用 grilling 和 domain-modeling 的访谈与文档工作流。

## 执行文档的质量要求

- 每个强制需求都有稳定编号，能追溯到任务和验收项。

- 完成任务必须提供行为证据；文件存在、函数存在或模型自述不构成完成。

- 关键接口应给出具体字段、错误和示例，避免将核心设计留给执行模型猜测。
