# 固定演示脚本

每个案例在独立测试 namespace/指定 reset 后执行。对话可以自然语言变化，但固定事实预期不变。seed-v1 基线见 ERP 契约。不要用关键词分支硬编码这些答案。

D03的前置夹具在测试准备阶段建立50件P001订单，记录真实order_id并提供给该案例对话，不依赖D02的执行顺序。D04单独准备一个未批准的创建候选动作。D06新用户namespace无偏好。D07新namespace无同名技能。夹具准备日志单列，不计作真实模型完成任务。演示现场可按顺序串联D02/D03，但自动24次评测必须彼此独立。

| ID | 用户输入与操作 | 必须发生与预期 |
|---|---|---|
| D01 | “查一下库存不足的配件，按目标库存给出补货数量。” | ERP/MCP 真查询；P001=42、P003=15、P004=30 |
| D02 | “为华东配件创建采购订单。”；补充“P001，50件，单价25.50元”；点击批准 | 信息不足先补充，再审批；批准前无单，批准后总额1275.00 |
| D03 | “把刚才订单数量改为60件，其他不变。”；点击拒绝；再次要求修改并批准 | 拒绝不改原单；最终1530.00、version=2、库存仍8 |
| D04 | 同一个创建审批，用两个浏览器 tab 同时批准；在写成功后模拟响应中断 | 仅一个订单；刷新查询得到同一编号，未产生第二次采购 |
| D05 | “比较缺货物料的供应商报价，按目标库存生成补货分析和柱状图，给我报告。” | 沙箱真实抓两站；推荐P001=S002、P003=S001、P004=S002，总额2553.00；报告/图表可下载 |
| D06 | “以后报告优先用表格。”；新会话再次查询；切 demo-b | demo-a偏好恢复；demo-b看不到其会话/技能/报告；偏好不串 |
| D07 | “创建一个补货金额汇总技能，分配给采购分析专家。”；随后用固定1533.00样例验证；重启API并重建沙箱，再要求使用 | 生成、测试、分配、Store持久化、恢复、读SKILL.md、执行脚本都有证据；只重读描述不算使用 |
| D08 | “后台生成采购分析报告。”；主对话问库存；查询后台状态；另启动任务并取消 | 主对话继续，后台可查产物；取消任务状态正确，无新工具调用 |

D07 之外，还需独立演示从资源目录下载技能 ZIP 的路径。skill scope 未提供时要询问，不能自动全员分配。测试失败修复、创建和下载都要覆盖。

## 给观看者的十分钟顺序

先展示真实库存与订单数据；走 D02/D03 看到两层人工介入；走 D05 看到多工具与沙箱报告；走 D07 看到技能跨重启恢复；最后展示 D08 和测试证据目录。时间仅为展示安排，不是开发工期承诺。

## 证据目录

每次 live attempt 保存 input.json、events.jsonl、final.json、assertions.json、服务状态和浏览器截图。对账脚本从 API/数据库获取 actual.json，与固定期望比较。订单号可以动态，但记录后用于后续查询，不能要求特定日期前缀。

截图只展示 Demo 数据。外部搜索查询使用通用配件保养背景，检查引用来源和结构，不断言公网搜索结果固定。
