# 主项目：采购 Harness 演示稿

建议时长 8–10 分钟。先打开 [真实证据回放 Demo](evidence-replay.html)，现场切换同一题的 fixed / skills / dynamic。演示的重点不是把页面点一遍，而是让面试官看到“模型怎么失败、系统怎么记录、下一轮怎么变、最后怎么验证”。

## 开场（约 40 秒）

可以这样说：

> 这是一个采购库存助手的 Harness。它背后有 Java Mini-ERP、MCP 网关、Mongo 持久化、OpenSandbox 和 LangGraph。我的重点不是让模型回答一句看起来合理的话，而是让每个决策都能落到 ERP 事实、审批边界和独立评分上。
>
> 我用一组故意比较难的采购题来做训练和评测。题目会同时考报价版本、包装数量、运费门槛、历史承诺、配套组和审批范围。

不要一开始说“三篇论文让我实现了自我进化”。先把系统和问题讲清楚，后面再说哪些机制受论文启发。

## 第一段：普通 Agent 为什么会错（约 1 分钟）

打开一题公开输入，展示需求、报价、ERP relationship、cart 和历史 commitments。让 fixed arm 输出一次。

讲解词：

> 这题最容易犯的错不是算术，而是把不同时间点的报价混在一起。还要区分报价里的 ERP 声明和 ERP 真实字段。模型可能会说“选了最低价”，但如果报价已撤销、还没生效，或者交期来自报价而不是 ERP，这个答案仍然不能执行。

展示 judge 的逐点结果，不要只展示一个总分：采购、来源选择、运费审计、历史账本、审批边界、ERP 冲突分别亮绿或红。

## 第二段：反馈如何变成候选技能（约 2 分钟）

展示一条 train 失败记录，依次打开：

1. public input；
2. Actor 原始输出；
3. 独立 judge 的失败字段；
4. Curator 可见的反馈和 execution trace；
5. 生成的候选 skill body 和 hash。

讲解词：

> Curator 不能看到 held-out 的答案。它拿到的是训练题、模型自己的输出、允许回流的诊断和真实执行轨迹。候选技能也不会直接覆盖生产 bank，先保存成隔离版本。

这里展示一段具体规则就够了，例如：

> 先按 as_of 和要求的 revision 过滤正式报价，再用 ERP 的 active、lead_days 和 capacity 做可执行性判断；运费只按本次新商品金额判断免邮门槛。

不要展示长篇生成文本，截取前后有差异的 5–8 行即可。

## 第三段：验证和选择（约 2 分钟）

展示 validation 表，再展示候选选择记录。

当前可以使用的数字：

| arm | validation 均分 | held-out 均分 | held-out 全题成功 |
|---|---:|---:|---:|
| fixed | 0.942308 | 0.758974 | 7/60 |
| few-shot | 0.792308 | 0.601282 | 0/60 |
| skills | 0.946154 | 0.876923 | 35/60 |
| dynamic selector | 0.965385 | 0.888462 | 35/60 |

讲解词：

> 候选是否保留只看 train validation 的总体表现，held-out test 不参与选择。test 每个 arm 跑三次，失败也留在分母里。dynamic 相比 fixed 的 held-out 均分高 0.129488；这说明在这组任务上有明显提升信号，但我不会把它说成统计显著，也没有把它自动发布到生产。

如果面试官追问“是不是挑了最好的一次”，直接打开 manifest，展示 repeat=1、2、3 和固定 bank hash。

## 第四段：进化如何进入真实执行（约 2 分钟）

展示一条 dynamic episode：

- 第一个回合选择哪个 skill；
- 读了哪个持久状态版本；
- 哪一次 computation 在 OpenSandbox 中完成；
- 预算修改后为什么旧审批失效；
- 最后订单是否通过审批和 ERP 校验。

讲解词：

> 技能不是一段塞进 prompt 的说明就结束了。它会跟 episode、bank hash、工具观察和 computation 版本绑定。计算失败时不发布结果，重新加载时从 Mongo 版本恢复，不依赖 Python 进程里还留着某个对象。

## 收尾（约 40 秒）

> 这个项目目前最可靠的结论是：我把一个有工具和状态的 Agent 做成了可评测的训练闭环，并在同一困难任务集上观察到了重复的 held-out 提升。它还不是通用自我学习系统，生产 assignment 也没有自动改变。下一步如果继续，我会补齐计算 Actor 的全臂对照和更独立的封存测试。

这句收尾比“我实现了三篇论文”更可信，也给面试官留下继续追问的空间。

## 演示前准备

- 预先打开一条 fixed 失败记录、一条 skill candidate、一条 dynamic episode 和最终 summary。
- 不在现场重新跑全量模型；现场只重放已保存的 evidence 和一条短任务。
- 备份一条服务不可用或格式失败记录，说明失败如何保留。
- 把模型名、任务集版本、repeat 数和 judge 版本放在 summary 顶部。
