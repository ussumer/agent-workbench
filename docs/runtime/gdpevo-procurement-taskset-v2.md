# GDPevo-inspired 采购困难任务集 v2

这是一组用于后续小模型校准的零模型设计资产，当前不包含模型成绩。公共任务材料在 [gdpevo-procurement-v2.json](../../fixtures/planning/gdpevo-procurement-v2.json)，私有评分控制在 [gdpevo-procurement-v2-control.json](../../fixtures/planning/gdpevo-procurement-v2-control.json)。Actor staging 只挂载前者的 `tasks`、请求、ERP 快照、报价和审批历史；后者不能进入训练或测试沙箱。

规则不是通用采购常识，而是澄川车队的企业约定：商务文件按正式版本和有效期选择、报价包装换算为单件需求、运费按本轮供应商购物车计算、维修配套组必须闭包、来源不确定性按是否影响决策处理，以及修订时保留已购承诺作为历史证据而不重复下单，当前追加量仍须当前 revision 的新审批。每条规则都有触发条件、证据引用、影响字段和停止适用条件，防止技能把局部动作泛化成“一律澄清”或“一律选最低价”。

任务矩阵是 5 个训练任务和 5 个测试任务。训练任务暴露规则子集；测试任务重组规则，至少三个规则组合没有在训练中共同出现，但每个测试规则都能追溯到训练锚点。测试数字、供应商、证据顺序和修订状态发生变化，不能靠复制答案模板完成。

每个留出任务有 6 个独立的二值评分点，权重为 1–3，分别覆盖可行性、分配、来源状态、已购差量、审批边界和证据引用。控制面保存 rubric，公共 fixture 不保存私有评分。8 个单因素反事实分别改变运费门槛、预算、价格边界、站点、报价状态、ERP 状态或配套组作用域；它们用于发现无条件澄清、重复下单、忽略包装和错误复用审批。

`python scripts/planning/gdpevo_taskset.py validate` 只做结构校验并输出输入 hash，`tests/acceptance/test_t52.py` 断言业务关系和隔离边界。该校验不证明 base 处于 40–60%、训练后提升 0.1–0.3 或最终低于 0.8；这些是后续固定模型、预算和环境后的校准目标，失败时应改题目关系或证据，而不是改权重或删失败。
