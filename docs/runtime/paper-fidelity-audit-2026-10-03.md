# 论文机制与现有方案的核对

日期：2026-10-03。状态：事实核查与修订建议，不自动扩大已批准业务或演化范围。

用户指出方案可能只模仿皮毛。核查使用 docs/papers/rsi 下固定版本原文、现有实施规格、应用装配和独立评测代码。Prime 与 GDPevo 由只读子 Agent 全文核查，主 Agent复核关键章节；TRACE 由主 Agent 核对正文、算法与实验协议。没有新增模型费用、服务操作或实验成绩。

## 结论

批评成立：旧规格有较完整的工程治理，但学习算法和可学习环境没有落到与论文贡献对应的实现要求。已完成 SE00 是协议与验收基础，不是三篇工作主体机制的实现。

- TRACE 是首期最直接相关的学习机制，但不能以“经验总结 + 检索”代替其初始化、按实际技能选择分组、逐轮更新与逐回合编排。
- Prime 是持续、程序化、递归运行时与轨迹期间适应的组合；只做来源、版本与回滚，没有覆盖主体贡献。
- GDPevo 是从训练经历恢复并组合企业惯例的评测设计；当前公开订单规则与规划条件矩阵不能单独证明这类学习。

工程工作仍有价值，不能用这些基础设施的测试通过证明算法忠实度或学习增益。

## Prime：不能把 L3 版本管理当作完整架构

本地依据：[§2.2–2.3](../papers/rsi/prime-agent/2608.23552v1.txt:185)、[§2.4](../papers/rsi/prime-agent/2608.23552v1.txt:250)、[§2.5](../papers/rsi/prime-agent/2608.23552v1.txt:263)、[§2.6](../papers/rsi/prime-agent/2608.23552v1.txt:309)、[附录 B](../papers/rsi/prime-agent/2608.23552v1.txt:955)。

| 论文机制 | 作用 | 现有方案缺口 |
| --- | --- | --- |
| L2 持久 IPython REPL | 程序化搜索/计算，中间值跨 turn 保留，只把必要结果送入模型上下文 | OpenSandbox 单次 shell 执行与文件持久化不等于持久 kernel |
| 异步 rlm 稳定 handle | 创建独立上下文、kernel 和历史的子会话，父代理继续执行，之后可随访 | 固定 YAML 子代理和只读 analyst 图不具备动态持久子会话语义 |
| daemon/session 树/消息队列 | 脱离客户端、压缩和恢复后继续通信与工作 | 当前未实现同身份递归拓扑及家庭范围持久消息协议 |
| typed L3 状态 | prompt notes、事实 memories、可执行 skills、subagent specs 分别管理 | 首期只允许文字策略，采用范围明显小于论文 |
| trajectory-time refinement | 从执行证据修订状态，在 turn boundary 生效，下一 invocation 使用 | 离线候选验证后晋升、任务中冻结是另一实验协议 |

版本、来源、回滚、不可改基础政策和主子资源记账可继续复用，但不单独提供程序化计算、动态计算分配或轨迹中适应。

原文 Factorio 报告了把作弊捷径固化成 Skill 的失败，说明持久化也会保留错误行为。nanoGPT 结果也没有证明整个 harness 在所有环境都产生明显收益。不能用总体结果为本项目文字策略方案背书。

**建议：**首期将 Prime 明确列为执行/状态生命周期参考，而非主体学习算法。若用户要采用其主体机制，需要单独确认持续目标、持久 kernel、动态子会话与任务中 refinement 的范围，并建立这些机制特有的行为验收与预算对照；不能在短订单任务里为凑论文名称强行添加复杂运行时。

## TRACE：首期需要补齐的机制

本地依据：[§2.1](../papers/rsi/trace/2608.22793v2.txt:115)、[§2.2](../papers/rsi/trace/2608.22793v2.txt:171)、[Algorithm 1/2](../papers/rsi/trace/2608.22793v2.txt:212)、[§2.3](../papers/rsi/trace/2608.22793v2.txt:262)、[§3.1](../papers/rsi/trace/2608.22793v2.txt:340)。

1. **初始化必须有中间产物。** 训练轨迹按任务提炼，按任务类型合并，再抽象为操作级能力，最后拆成聚焦技能。每一阶段留下来源映射、拆分/合并理由和正文，不能只调用一次 LLM 总结后命名 Skill Bank。可以调整调用数量与训练规模，但要披露与论文的差异。
2. **每个 Actor 模型回合重新编排。** 在下一次动作生成前，根据当前历史和全部作用域内的技能描述，选择有序技能 ID 序列，再按序读取精确版本正文，注入本次调用。这里的 turn 是模型动作回合，不是一次用户消息或一次 API run。下一回合重新决定，不累计上一回合正文。一次相似度检索、目录发现或读取 SKILL.md 不能替代这一步。
3. **归因依赖实际选择。** 记录 actor/session/run/turn、bank hash、可用技能描述集合、选中 ID 与顺序、正文 hash、后续动作及观测。主子 Agent 分开作用域；skill 存在、被选择、被读取和实际效果分别记录。轨迹分组是关联证据，不自动证明某一技能造成整任务失败。
4. **每轮从当轮 bank 收集新轨迹。** B(r) 执行 train → 按实际技能使用分组 → 分成功/失败 → 修订或拆分 → 检查新 bank。缺少成对记录时披露不足，不虚构；没有技能或未知技能的轨迹独立进入缺失能力发现分支，而不是扔掉。
5. **保持 Actor 可见视图。** 当时工具/参数/结果缺失、未解决约束与公开政策必须可恢复。允许给 Curator 的诊断特权信息单独标记；本项目已选择有限诊断，不提供完整答案，需要披露该监督差异。
6. **去除硬编码要保留作用域。** 不仅删除订单 ID/数值，也要检查具体答案、环境特殊值和无条件化的策略。任务规则的适用条件及合法业务常量不能机械全部删除。

选择器应作为独立固定运行机制接入现有模型调用 middleware，额外请求纳入统一预算；不能偷偷改基础政策或让 Curator 修改选择器代码。小 bank 评估所有描述符合论文机制，扩展 bank 后的缩放问题要另作实验。

**实验边界的重要纠正：**TRACE §3.1 的公开结果使用训练和测试集合扩展技能覆盖，并报告两者合并结果，不是干净的 held-out 指标；独立泛化证据来自 §3.3 的官方 hidden set。本文保留训练/验证/封存隔离，比其公开优化协议更严格，但不能直接拿公开高分作项目目标。论文指标按任务类型宏平均，本项目还需同时报告微平均及样本数。

**归因不足：**原始经验 vs 提炼技能只能证明提炼整体的差异。要证明层级抽象和成功/失败对照的贡献，还需同模型、同训练资料、同反馈与学习预算的简单总结基线，以及逐轮编排的开关对照。首次三组验收不因此失效，但不能作机制因果证明。

多轮演化会生成新的训练轨迹，原规格“B/C 同一批训练记录”的描述必须具体化。应明确共享语料基线与交互式多轮实验的不同协议；若给检索组共享多轮语料，需清洗已注入的提炼正文，防止把技能内容直接泄露进所谓原始经验组。训练轨迹数与学习计算量均记录，不能把不等经历的结果解释为纯提炼贡献。

## GDPevo：先证明环境有东西可学

本地依据：[§3.2–3.4](../papers/rsi/gdpevo/2608.03764v1.txt:285)、[§4.1](../papers/rsi/gdpevo/2608.03764v1.txt:375)、[RQ3](../papers/rsi/gdpevo/2608.03764v1.txt:570)、[F.3/F.4](../papers/rsi/gdpevo/2608.03764v1.txt:1159)、[G.1–G.4](../papers/rsi/gdpevo/2608.03764v1.txt:1235)。

- 论文原子规则含企业内部惯例，训练暴露子集，测试重组；当前任务把审批、澄清等政策直接公开。当前可以测策略遵从和经验复用，但不能称隐藏惯例恢复。
- 当前 matrix 条件没有 train/test 实例 ID，R_EXACT_ORDER 又捆绑多个决策。规划矩阵不是可归因的 task–rule matrix。
- 每个测试能力须对应训练锚点：训练暴露的知识、触发证据、作用域、控制的输出、测试变化与新交互。只有换实体/数量不能证明新组合。
- 增加反事实适用性验证：缺数量 vs 数量明确；超时未提交 vs 已提交但丢响应；用户拒绝 vs 合法批准；历史供货关系 vs 当前改变。检查技能是否把“问、重试、拒绝”无条件泛化。
- 当前 rule_pass_rate 对订单正确与无额外写入有语义重叠，补充回复消费也不等于正确询问字段。全强制任务成功可保持，独立知识掌握 rubric 要拆分并用逐项业务变异验证。
- 项目的有限结构诊断应命名 diagnostic-reflection，不能冒称论文 score-only reflect；方法组与监督条件继续分开。
- 学习重复与执行重复分别统计；拒绝候选、校准、选择和失败学习的成本不能只记最终成功候选。

**建议前置学习问题设计：**在真实 Curator 前先完成原子知识/条件、训练锚点、可解性、独立评分和校准。SE05 的任务设计部分应拆出并成为 SE03 的前置依赖，封存网络隔离可以继续后置。保留所有校准结果，不通过改 rubric 权重或淘汰无增益任务制造漂亮成绩。

在已接受业务范围内，先明确有哪些策略知识并未由任务提示逐步教完，并证明训练证据可以迁移。若这条路线缺少学习空间，再由用户决定是否增加隐藏企业惯例的独立场景；不能偷藏审批/权限政策或仅在私有裁判中添加无法推断要求。

## 对当前实施的处理

SE00 的契约、组身份隔离和严格 gate 可以保留。SE01 通用证据采集可继续，但必须为逐回合选择与 Actor 可见视图预留可验证字段。已通知实施 Agent 不按旧稿落实 SE03/SE04 算法，在选择接口或学习问题确定前提交审阅。

旧规格保留为已接受 v1，不自动把本核查的新增实验和业务范围当作用户授权。需要修订的主体是学习算法、任务设计前置依赖与论文采纳声明，而不是继续增加无关日志/哈希功能。
